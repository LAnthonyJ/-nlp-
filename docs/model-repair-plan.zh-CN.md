# Qwen2.5-0.5B 训练与评测修复计划

基线提交为 `52738f8`。本轮要回答两个问题：在同一个 Base 上重新做监督微调（SFT），能否改善未见题上的正确率和指令遵循能力？从这份 SFT 权重继续做偏好优化（DPO），能否带来额外收益？以下数值是实验设计与验收门槛，实际成绩待运行后填写。

首轮的 420 条正式回答显示，旧 SFT 在 30 道数学题中有 5 道能提取到正确数值，严格协议下为 0 道；逻辑和代码分别为 0/25、0/25。25 个参考程序都通过了同一代码评分器。数学格式、实际解题能力和可运行代码都需要单独验证。正式推理使用 Hugging Face 的 Qwen 和 PEFT 权重，因此本轮改动集中在实际经过的数据、训练、推理和评分路径。[首轮结果与限制](capability-results/README.zh-CN.md)

## 1. 固定基线，建立独立评测

- 给现有 `python -m nlp_course.capability` 增加可选的实验配置。将模型版本、适配器、模板、停止符、任务集和输出目录显式传给生成、评分、分析、盲评及绘图各环节，消除固定三个阶段和本机课程路径的假设。无新配置时仍可用旧命令重绘首轮报告。
- 新实验写入独立目录。续跑前比较模型、适配器、tokenizer、模板、题目、解码参数及协议哈希；拒绝混用记录，能够从最后一条完整记录继续。正式报告须校验所有预期模型和题目均有唯一记录，显示缺失、未评和截断的数量。Docker 不可用时标记代码未评。
- 冻结新英文保留集：从首轮未使用的 GSM8K test 和 HumanEval 各抽 30 和 25 道；新增 30 道逻辑题，其中 10 道判断题正反各半，10 道排序、10 道计数，打乱事实顺序，程序求参考答案。开放题另设 10 道概念、10 道写作，以盲评为准。先固定 ID、种子 42、参考答案、评分规则，再开始选模型。另建开发集，从 GSM8K train 的预留部分、自编函数和独立逻辑模板取题；首轮已分析题仅作历史诊断。
- 在相同新题上评估 Base、旧 SFT、旧 DPO、新 SFT，以及满足训练条件的新 DPO。课程模型使用相同的英文指令和课程模板。增加同规模官方 Instruct，用其原生模板作外部参照，单列模板差异。统一 greedy 和输出预算，默认 256 token；参考程序预先通过现有隔离容器校验。最终集仅在配置和候选模型锁定后运行。

## 2. 将训练数据处理移入仓库

- 新增 `python -m nlp_course.training prepare --config <配置>`。读取现有两份各 1,000 条的课程数据，输出带稳定 ID、来源、题型和划分的 SFT 及偏好样本。输入缺失、格式错误、候选答案相同或没有可训练回答时给出原因；禁止用占位数据补足数量。
- 对重复提示、同题改写及相同生成模板分组。固定种子按组分出训练集与验证集，SFT 和 DPO 共用分组边界。与历史题、新开发题及最终题做精确和近似重叠检查，复核命中项，保存排除清单和划分哈希。公开摘要只含计数、来源与允许公开的例子。
- 对 193 条疑似“生成偏好对”元指令逐条复核，也检查未命中规则的样本。偏好对只有在两份回答针对同一用户需求、优劣方向可解释时才进入训练。客观题记录验证方法；主观样本记录人工理由，理由不足的隔离。对 SFT 的错误答案、代码不完整和格式矛盾同样处理。
- 按开发题型补充可验证的数据：数学使用 GSM8K **训练划分**的独立题，逻辑用可求解的生成器，代码用附带测试的自编函数。课程开放题只用审过的回答。清单给出每类纳入、淘汰和补充数量。首轮数据制作和训练均可本地完成，下载公开数据后固定版本与哈希。

## 3. 修正 SFT 的训练目标，先证明模型能学到

- 将 notebook 中的训练逻辑迁入 `python -m nlp_course.training sft --config <配置>`。训练和推理共用提示编码函数；对一条样本逐 token 检查：用户提示、角色前缀及 padding 标签均为 `-100`，助手回答和一个实际结束符参与损失。保存模板、特殊 token ID 和适配器。推理使用同一结束符。超长样本缺少完整答案或结束符时排除并计数。
- 单独锁定可运行的 GPU 训练依赖；保留现有 CPU 测试环境和 GPU 评测环境。首选现有 PyTorch、Transformers、PEFT 组合和标准因果语言模型损失。6 GB 显存先测一个完整优化步、一次保存和重载。初始配置为 LoRA rank 16、alpha 32、注意力 q/k/v/o 投影、单卡微批 1、梯度累积 8、长度 512、梯度检查点、学习率 1e-4。记录实际精度、峰值显存、吞吐和剔除的超长样本。显存不足先排查缓存及冻参，再按完整样本长度分桶，重新做小样本验证。
- 从训练部分固定取 16 个答案短且唯一的样本，最多训练 200 个优化步。重载适配器后，greedy 至少答对 14/16 才开始正式训练。失败时依次检查输入与标签对齐、结束符、可训练参数的梯度、参数更新及重载前后输出。这个门槛只验证训练链路。
- 做两个 SFT 对照：A 用通过基础校验的原课程数据和新训练代码，B 使用清洗、补样后的数据和相同代码。两组固定起点、随机种子、更新步数上限及有效批大小，记录实际监督 token 数。每 50 步及训练结束评开发集，以数学严格正确率、逻辑准确率、代码测试通过率的等权均值选 checkpoint，同分取较早者。旧权重与 A 的差异包含多项训练条件变化，A/B 比较估计的是整组数据调整的效果。

## 4. 让 DPO 的偏好方向和参考模型可验证

- 增加 `python -m nlp_course.training dpo --config <配置>`。以选中的新 SFT 为策略起点，也以它的冻结快照为参考。先用冻结 SFT 在评估模式预计算每对回答的参考对数概率，释放参考模型后训练策略适配器，降低显存压力。缓存绑定参考权重、样本、编码和截断策略的哈希。
- 两个分支共享完全相同的提示，只累计回答和结束符的对数概率。用小张量验证损失计算、交换优劣后梯度方向反转、初始策略与参考分数在容差内一致、一步更新后参考值不变。初始学习率 5e-6、beta 0.1，最多一轮；记录偏好准确率、奖励差、重复与截断，并用 SFT 相同的开发题复评。
- 只有当 SFT 已通过小样本验收、开发集客观均分超过旧 SFT，且审过的偏好对能划出独立验证集时，才运行正式 DPO。DPO 的开发集客观均分须高于 SFT，且任一客观任务不能下降超过一道题，才选为展示候选。否则展示 SFT，并记录退化的题型。此规则用于选模型，不能证明统计显著性。
