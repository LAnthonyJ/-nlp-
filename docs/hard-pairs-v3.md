# Standard DPO with model-ranked hard negatives

The starting adapter is the selected SFT step 64 of the completion-boundary experiment. Each candidate starts afresh from that adapter. Standard DPO uses a frozen copy's reference scores precomputed before the optimizer steps and the original sigmoid preference loss with beta 0.1. The separate chosen-only control uses the same shuffled rows and learning-rate grid.

## Reproduction

Restore the input directories in [the configuration](../configs/hard-pairs-v3.json), including the verified v2 return. Set `PROGRESSION_BASE` to the pinned local Qwen Base snapshot. Use the existing SmolLM2 preparation environment for the first command and a BF16 CUDA training environment with a compatible PEFT reader for the remaining commands. For public instruction grading, expose the pinned LightEval instruction registry, langdetect and NLTK English punkt resources as in [the public experiment](progression.md).

```sh
export PYTHONPATH=src:upstream NLTK_DATA=upstream/nltk_data HF_HUB_OFFLINE=1
python -m nlp_course.hard_pairs prepare
python -m nlp_course.hard_pairs collect
python -m nlp_course.hard_pairs run
python -m nlp_course.hard_pairs public
```

Preparation excludes prior banks, public questions, repeated HellaSwag video sources and SVAMP story groups. The four new task partitions each contain 48 development and 192 holdout prompts. The instruction exercise uses separately worded development and holdout templates for five skills. It is a custom task. The historical full-suite replication uses official IFEval and GSM8K.

Collection reuses responses generated by the exact starting SFT. For choice tasks the SFT must select the wrong answer under the public scoring rule. For generation tasks its nonempty, completed greedy output must fail the verifier. Prefer a verified sampled positive; for instruction tasks a program-verified demonstration is available as fallback. Keep pairs with token-length ratio at most 1.5 and negative reference sequence-log-probability margin under the actual training encoding including EOS. Within each family sample the closest such decisions first, prioritizing model positives, then round-robin across families. Each task contributes at most 128 pairs.

Each learning rate (0.00002 and 0.00008) receives one epoch, effective batch 16 and microbatch one. Four development checkpoints are evaluated. Configurations passing the development gain and per-task regression gates rank first, followed by macro accuracy, earlier step and lower learning rate. Lock the best DPO and best chosen-only weights before evaluating the new holdout once. Primary acceptance uses the inherited 1 percentage point DPO gain, at most 2 points of decline on any task and a positive multiplicity-adjusted lower bound. Report paired two-sided 95% intervals as well. Cached batches, adapter hashes, row identities and per-task changes are under `outputs/hard-pairs-v3`. The same-device public comparison runs after the lock, with SFT and DPO using identical scoring settings.
